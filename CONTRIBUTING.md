# Contributing

1. Read the roadmap and data contract before opening an issue.
2. Add or update tests for formulas, parsing, API contracts and evidence provenance.
3. Keep synthetic fixtures separate from real-source records.
4. Do not commit API keys, PDFs, databases, model caches or full extracted corpora.
5. Report measured metrics with the dataset version, model version, hardware and sample counts.

Small pull requests are easier to review. Each PR should describe the user-facing behavior and verification command.
