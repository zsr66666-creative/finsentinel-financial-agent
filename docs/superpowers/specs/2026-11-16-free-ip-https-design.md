# Free IP HTTPS design

Scope: user's approved zero-additional-domain/certificate-cost path for existing ECS public IPv4 120.24.108.60. Official Let's Encrypt January15/March11 2026 announcements support public IP, 160h shortlived certificates and Certbot >=5.4 webroot. User supplied valid Nginx single HTTP server_name IP, port80 only, no Certbot. Existing backend/frontend/worker/encoder remain untouched.

Use isolated Certbot venv (pinned published 5.10.0, Python>=3.10), webroot HTTP-01, separate staging account/storage and production lineage finsentinel-ip. Back up Nginx and managed renewal files before mutation. Renderer accepts only single HTTP server block with exact configured IP and supported port80 listeners, retains existing locations/proxies/limits/comments, adds challenge location and cloned TLS server. Refuse ambiguous/multiple/includes/SSL configurations instead of replacing arbitrary services. Nginx syntax-test then reload, never stop/restart for challenge. Preserve HTTP until external443 success; no automatic redirect in this phase. Domain, registration/account identity and application behavior unchanged.

Stage challenge endpoint locally, staging issuance then production issuance; configure TLS1.2/1.3 using issued files. Validate certificate trust, IP SAN and expiry over loopback connection with publicIP SNI/hostname, plus app shells and static assets and health/scopes. Never disable certificate validation. Configure systemd renewal every12h with randomized delay, Persistent=true, dry-run including Nginx reload hook. Short expiry requires automation. Installation failure restores pre-run Nginx/managed units and timer state; issued certs/accounts/venv remain (not destructively removed).

Operator must allow public TCP443 in ECS security group and any active host firewall; script reports, never opens other ports or changes firewall/security group. Current public443 timeout is observational, not proof which layer blocks. Public80 must remain reachable for HTTP-01. No HSTS/redirect until external acceptance. No auto fallback to untrusted staging/self-signed cert. Signing accepts CA subscriber agreement noninteractively; no email registered, automated expiry checks documented.

Delivery: source-only offline package of installer/helper/docs/tests with checksum; no key/cert/token. Unit tests cover renderer preservation/refusal/idempotency and TLS verification boundary, GitHub CI bash syntax and complete backend tests. Local Windows may block bash subprocess; actual ECS signing, renewal and external443 acceptance remain pending.
