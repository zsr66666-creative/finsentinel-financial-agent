# FinSentinel 自动备份与运行监控设计

## 范围与方案

沿用用户确认的范围：数据库定时备份、保留策略、恢复验证；关键服务与证书检查；管理员状态页；部署到阿里云。首期不接入外部通知，不新增收费服务。
推荐 systemd timer + Python 检查器 + JSON 状态文件。相比 Prometheus/Grafana，该方案适合当前约2GB服务器，依赖少；相比单纯cron，systemd可记录失败、限制运行时间并补执行错过的任务。
本阶段服务器本地备份不能抵御整机或磁盘丢失；异机副本另行实施，不宣称已有灾备。

## 定时备份

每天北京时间03:30执行，使用明确 Asia/Shanghai 时区；持久化timer并加入短随机延迟。root专用目录 /var/backups/finsentinel，权限0700，文件0600，禁止Web访问。
采用 pg_dump 自定义格式，并在包中记录时间、版本、文件大小和SHA256。数据库包括用户、复核与业务表；备份属于敏感资料，网页不提供下载。
归档采集原始文件及与当前数据库对应的必要来源元数据，保留可重建索引的输入；不把git仓库或.next构建当成原始资料。备份必要服务/环境配置时保持root-only，不在日志/网页显示内容。证书私钥不经API暴露；恢复证书可按现有签发流程进行，敏感配置独立受限归档。
为防并发采集导致数据库与文件不一致，备份需核验数据库引用的原始文件存在且SHA匹配，缺失或变化则本次失败，不发布为有效恢复点；不为备份停止业务服务。文件归档按数据库引用清单确定，不盲目复制整个目录。
先检查空间，再写临时目录；各阶段带超时和同任务互斥，成功校验后原子发布。失败不替换最近有效备份，不删除旧备份。
保留最近7个每日成功恢复点；只有新备份完整发布后才清理超出策略的受管恢复点。清理验证绝对路径、受管标记、文件名和无symlink，绝不删除目录外文件。空间不足时记录失败，要求人工处理，不自动删除未知文件或停服务。

## 恢复验收

首次部署和此后每周日北京时间04:30验收最近成功备份。恢复到严格命名的独立测试数据库，绝不覆盖生产数据库。
预创建vector扩展，沿用 pg_restore --no-owner --no-privileges --no-comments。核对备份清单哈希、schema、同一快照的表计数及原始文件引用，检查账户/复核/向量表可读取。
不以表计数相同宣称应用全量恢复或逐行数据完全一致。测试数据库不接入线上应用，不重启worker。
成功后清理此次专用测试数据库；失败保留诊断摘要，专用临时资源有受控保留策略，不能每周无限堆积测试库。清理限定当前任务创建且有标记的库，记录失败并等待维护者处理。

## 健康监控

每5分钟检查一次，单次总超时不超过2分钟，进程互斥。检查 nginx、backend、frontend、ingestion-worker、query-encoder、证书续期timer及备份/恢复timer；oneshot服务不使用is-active单独判断失败。
检查数据库SELECT1、受信TLS的本机HTTPS健康与登录页面/关键静态资源、encoder健康、根磁盘可用空间、最近备份及恢复时间、证书剩余有效期和最近续期任务结果。
证书通过公共IP SAN和系统CA信任验证，不使用-k。证书剩余不足48小时warning，不足24小时critical；不能把timer启用等同续期成功。备份距今超过30小时warning、超过48小时critical；首次未完成显示unknown。恢复超过8天warning。磁盘剩余低于20%或4GiB warning，低于10%或2GiB critical。
结果使用ok/warning/critical/unknown，每项包含检查时间、简短原因、耗时；不含密码、令牌、账号信息、SQL原始输出、私钥、环境变量或完整日志。
本机HTTPS检查不能证明公网安全组或用户网络可达；在页面明确展示该限制。

## 状态与异常记录

状态文件由root检查任务原子写入 /var/lib/finsentinel/operations，目录0750 root:finsentinel，文件0640；应用仅有读取权，无systemctl/root执行权限。
最近检查摘要与异常状态变化分开记录；状态变化记一条，恢复也记一条，历史最多200条。重复故障不每5分钟无限追加。
管理员API GET /api/v1/admin/operations，只读返回清洗过的摘要和历史。auth未启用时此API仍拒绝匿名访问；管理员鉴权不能依赖仅前端隐藏入口。
若文件缺失、格式错误、版本不支持或超过15分钟未更新，显示unknown或critical及原因，不显示绿色成功，不泄漏文件原文。API no-store/nosniff。
管理员页面 /admin/operations 提供手动刷新、最近备份/恢复、证书到期、服务与磁盘卡片、异常历史；普通用户403。没有网页执行备份、恢复或shell命令入口。

## 上线与测试

先写失败测试：保留清理边界、失败不清理、symlink/路径拒绝、过期/未知状态、异常去重与容量、API权限和信息脱敏。恢复测试和备份测试必须在隔离库/临时目录，不伪造生产复核。
Linux CI验证shell语法、后端完整测试、前端单元测试与生产构建，并使用PostgreSQL验证备份/恢复核心契约。
升级包只含已提交源码及校验清单。部署器备份旧配置与构建，预构建后切换，保留HTTPS/账号/业务数据/向量；失败回退旧代码、构建、受管units及timer启用状态。
首次服务器备份和隔离恢复实际成功后才启用定时任务，执行一次健康检查，然后验收管理员API及页面静态资源。备份文件、凭据、生产数据不进入GitHub或聊天。
实际服务器验收与浏览器验收分别报告，不能把本地/CI通过称为已上线。
