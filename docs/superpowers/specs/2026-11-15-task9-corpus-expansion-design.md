# Task 9：真实报告索引与可选择检索范围

## 已批准目标

将已采集的立讯精密 2024FY 官方报告纳入文字检索；用户可选择实际可检索的公司和期间；保持既有 2026H1 检索及已复核金额比较。所有交付包含阿里云部署及验收。

## 代码核对发现

- `ingestion_artifacts` 仅记录已解析产物，采集成功不代表向量索引已建立。
- 现有 PDF 解析器最多选取 14 页，返回物理页码、原文、块偏移、PDF SHA-256、解析范围及质量标记。因此首次接入应明确标注“选页覆盖”，不能称作全年报全文检索。
- 前端文字检索请求和说明固定为 `002475 / 2026H1`。
- 当前在线编码器对问题添加检索前缀；文档编码必须采用不加问题前缀的独立路径，不能直接调用问题接口给文档建索引。

## 路线取舍

1. 推荐：先为已有解析产物建立可追踪的选页索引，同时提供真实范围目录。改动有边界，可验证，并沿用现有采集与查询模型。
2. 立即全量重解析和索引：覆盖更广，但需要额外的逐页质量审核、长表切分与资源验收，独立安排在下一阶段。
3. 仅增加公司/期间下拉框：不能解决实际索引缺失，不采用。

## 数据流程与一致性

受控管理员命令读取指定 artifact ID，验证数据库元信息、解析 JSON 和原始 PDF 哈希。按已有物理页码和块偏移切分，长块进一步切分并保留准确起止偏移；不跨页拼接，不虚构报表口径。

使用固定版本 BGE、512 维、CLS、L2 归一化；文档不添加查询前缀。复用 ONNX 运行时，单进程、逐批限流；不在 API 进程加载模型。索引作业与线上查询避免同时占用第二份模型，部署脚本在维护步骤控制执行并恢复服务。

先完成校验和向量计算，再在数据库事务中发布整份报告索引及覆盖记录；失败不发布部分报告。片段身份包含文档身份、切分版本、页码和偏移。相同输入重跑不增加重复行；发现相同身份内容不一致则失败。保留现有 14 条向量及所有已复核证据，不覆盖旧索引。

每个片段保留公司、报告期、document ID、PDF SHA-256、原文 SHA-256、来源 URL、采集时间、物理页码、偏移、提取方法及质量状态。保留未复核状态，采集/索引成功不提升为金额已核验。

## 检索目录与前端

增加只读检索范围 API，只返回固定模型下已经成功发布、实际存在向量的公司/期间。既有向量提供兼容目录项，并明确其片段覆盖。目录返回片段数、已索引页码、覆盖类型和来源状态。

公司和报告期为联动选择，切换范围清空旧结果；请求绑定所选范围，取消或忽略过期响应。目录加载失败显示可恢复错误，不伪造选项。无索引的企业不出现在“可检索”列表。保持 macOS 样式、明暗主题及移动布局。

已复核金额比较继续独立使用原有接口和支持范围。新报告检索结果只是候选原文，不自动获得金额比较能力。

## 验收与部署

- 单元/集成检查：错误哈希拒绝、偏移和物理页码一致、文档无查询前缀、512 维有限归一化向量、重复执行幂等、事务失败无部分发布、跨公司/期间隔离、目录与索引一致。
- 前端检查：目录联动、空范围/错误状态、切换时旧结果不串入、TypeScript、单元测试、生产构建。
- 阿里云：先备份；独立发布目录；沿用已有 ONNX 文件，避免 GitHub 逐文件下载；Shell 固定 LF 并在打包后检查；部署失败回滚服务和前端构建，保留诊断产物。
- 验收实际 2024FY 页码与原文、2026H1 回归、重复建索引行数不变、Nginx 页面和全部静态资源、文字检索接口与已复核比较接口、服务内存和重启次数。
- 独立测试题保持冻结；开发冒烟题和正式评测结果分开报告。

## 后续范围

互联网/高新技术企业在本次链路通过后分批采集官方报告。每家先验证上市主体、报告期、来源和抽样页码；不把待采集名单当作已有数据。港股/美股主体的来源适配另行处理。全量页索引和更多企业分别验收。
