# 原文到数值比较的限定验收

用户已在聊天中确认：物理页 62 为母公司资产负债表标题；页 63 应收账款两列分别为 5,313,841,643.82 和 5,620,343,695.37；两列日期为 2026-06-30 和 2025-12-31，单位为元。本记录补充人工复核状态，不覆盖此前仅文本核验的历史结果。

流程：锁定 PDF 哈希 → 完整提取页 60–63 → 识别报表标题及连续页口径 → 精确定位应收账款行 → 校验紧邻的同页同口径两列数值 → Decimal 比较 → 返回标题页和数值行的审计定位。

实测 7/7：母公司及合并各自的 greater=False、not_greater=True；混合口径、缺少来源、未来预测关系均返回 needs_review。应收账款母公司减少 306,502,051.55 元，合并减少 772,501,509.62 元。结果保存在 `data/evals/week04-source-comparison.json`。

运行方式（需私有原始 PDF，PYTHONPATH=backend;.）：

```text
python scripts/week04_source_comparison_check.py --pdf <PDF路径> --output data/evals/week04-source-comparison.json
```

边界：脚本接收明确的指标、口径和关系，不解析任意自然语言；公司、日期、单位为该哈希文件的复核契约，不是自动抽取；行定位不是持久化 chunk ID。单份已知 PDF 的开发验收不能证明泛化能力。线上 API、数据库和网站未变更。

后续接入前需把审计行与数据库真实 chunk ID 对齐，并验证自然语言请求到明确查询条件的转换；不能直接把本结果宣称为生产问答完成。
