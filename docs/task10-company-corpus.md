## 数据与页面

- `research_companies.py` 只提供发行人身份和业务标签，不代表已采集或已索引。真实研究库仍完全由实际固定模型向量生成。
- 首页面向用户显示独立的“真实报告研究库”，包含实际企业、报告期、业务领域和片段数；旧监控指标与演示公司研究库继续明确标注为演示。
- 新增公司详情 `/companies/002555`、`/companies/002230` 仅在确有索引后返回真实候选资料，提供公司限定的原文检索，不生成指标、告警或数字结论。立讯公司页也提供真实原文检索，原有监控指标仍按其演示数据模式标注。
- 问题、公司、报告期绑定；换公司/期间或修改问题取消旧请求。公司详情的高级查询包不能切换到其他公司；返回范围不匹配的结果拒绝展示。

## 采集与部署

`scripts.task10_acquire` 是管理员 CLI，使用既有持久队列和常驻 ingestion worker。两份请求使用固定独立幂等键；重跑复用任务，不重新排队新副本。等待有界，失败时保留队列/诊断；只有 success/committed 且公司、报告期、URL、PDF 哈希和 document ID 全部匹配时进入索引。URL 内容发生改变时停止，不自动接受新哈希。

Task 10 包不含 PDF、模型、向量、数据库或凭据。`install-task10-offline.sh` 调用共享 Task 9 安装器的受限 task10 模式；默认 task9 行为仍保留。源码包逐文件校验，Shell 固定 LF。云端重新从官方站点采集两份报告，先完成数据库备份，再复用原有 Task 8 模型与编码环境；文档编码期间暂停 resident encoder，失败路径保证启动恢复。逐报告执行首次/重复索引校验，不覆盖旧片段。

构建完成才切换前端；后端与前端失败恢复旧配置和构建，已提交的新增任务、产物和索引保留，不自动破坏性恢复整个数据库。保留完整 dump、索引报告及验收 JSON。无需修改 Nginx 或开放新端口，也不修改现有 ingestion worker 服务。

三七的选页解析记录包含空白封面，索引覆盖页码剔除了没有文本片段的第 1 页。总计新增 708 个片段。文档编码无问题检索前缀、无 torch，固定 512 维 ONNX CPU，本机单独进程峰值约 226 MiB。全部原文均重新与原始 PDF 页文本核对。两家公司各运行营业收入、应收账款和经营现金流的已知来源开发冒烟查询，返回 Top-5 含对应原文并保持公司隔离。

本地 API 联调使用 TestClient、SQLite 和 NumPy 精确余弦，再接实际混合检索与 ONNX；不等同云端 PostgreSQL。针对性后端测试 55 通过、2 跳过（没有专用 TEST_POSTGRES_URL）；前端 23 测试与 TypeScript 通过。Windows 的既有 spawn EPERM / Git Bash signal-pipe 限制下，生产构建和 Bash 执行保留为云端步骤；所有部署内嵌 Python 和归档 LF 另行检查。

`scripts.task10_acceptance` 在云端先跑 Task 9 回归，再核对新增报告全体片段、目录、企业详情无伪造指标、六个开发冒烟问题的真实 BM25+pgvector RRF 和公司隔离。Nginx 验证七个页面及其 CSS/JS。云端、独立评测和人工交互在实际完成前保持 pending；选页搜索没有命中不代表报告未披露，也没有新的已复核财务结论。
