# FinSentinel v0.2 项目规划

建议用 **8 周**完成，重点从“可演示候选版本”升级为“真实数据、真实模型、可部署版本”。

## 第 1 周：真实 LLM 接入

### 任务

- 统一模型 Provider 接口；
- 增加 API Key 环境变量管理；
- 实现超时、重试和失败降级；
- 保存 prompt、模型版本和耗时；
- 禁止模型直接执行未授权工具；
- 保留 FakeModel 作为默认测试替身。

### 验收

- FakeModel 和真实模型可以切换；
- 模型失败时返回可解释错误；
- 模型结果不会被标记为已核验事实。

## 第 2 周：真实 LLM 对照实验

### 任务

- 使用同一批黄金问题；
- 比较单 Agent、双 Agent 和确定性工具；
- 记录命中数/总题数；
- 记录 p50、p95 延迟和失败率；
- 单独记录 API 成本。

### 验收

报告必须包含：

```text
质量：命中数 / 总题数
性能：p50 / p95 延迟
稳定性：成功数 / 总请求数
```

## 第 3 周：PostgreSQL 迁移

### 任务

- 将 SQLite 数据模型迁移到 PostgreSQL；
- 增加索引和迁移脚本；
- 保留 SQLite 作为本地轻量模式；
- 增加数据库连接失败提示；
- 增加迁移回滚验证。

### 验收

- 空数据库可以完成迁移；
- 关键 API 在 PostgreSQL 上通过；
- SQLite 和 PostgreSQL 返回结构一致。

## 第 4 周：pgvector 检索

### 任务

- 增加文档 chunk embedding 表；
- 使用 pgvector 保存向量；
- 实现向量 Top-K 检索；
- 与 BM25 做 RRF 混合；
- 记录向量模型、维度和耗时。

### 验收

- BM25、向量、混合检索分别评测；
- 使用同一黄金问题集；
- 报告 Recall@5、Recall@10 和漏检原因；
- embedding 失败时回退 BM25。

## 第 5 周：后台采集任务

### 任务

- 增加后台采集队列；
- 支持 `pending`、`running`、`success`、`failed` 状态；
- 增加重试和断点续跑；
- 保存来源 URL、抓取时间和 SHA-256；
- 增加官方域名白名单。

### 验收

- 重复采集不会生成重复文档；
- 失败任务可以单独重试；
- 超时、重定向和非法来源会被拒绝。

## 第 6 周：真实公司扩展

### 任务

- 从当前 5 家扩展到 10–15 家；
- 每家公司准备年度报告和公告；
- 统一报告期、币种、单位和合并口径；
- 为新增公司补充黄金问题；
- 保持公司级和期间级过滤。

### 验收

- 错公司材料不会被召回；
- 未来公告不会污染历史分析；
- 同业比较明确标注口径差异。

## 第 7 周：生产部署和安全

### 任务

- 完成 Docker/Podman Compose；
- 增加 PostgreSQL 和 pgvector 服务；
- 增加健康检查和数据库依赖检查；
- 配置密钥和日志脱敏；
- 增加限流、文件大小限制和 SSRF 防护；
- 配置 GitHub Actions 部署检查。

### 验收

- 新机器可以按 README 启动；
- API 和前端健康检查通过；
- 数据库重启后服务能恢复；
- 敏感配置不会进入 Git。

## 第 8 周：v0.2 发布验收

### 任务

- 重新运行全部后端和前端测试；
- 完成真实 LLM 评测报告；
- 完成 BM25/向量/RRF 对照；
- 完成真实用户试用；
- 完成浏览器视觉验收；
- 更新架构图、README 和限制清单；
- 创建 `v0.2.0-rc1` 标签。

### 最终交付

```text
真实 LLM 评测报告
向量检索评测报告
PostgreSQL 迁移记录
后台采集任务记录
用户试用报告
Docker 部署记录
v0.2.0-rc1 Release
```

## 推荐执行顺序

```text
真实 LLM 接口
→ 真实 LLM 对照实验
→ PostgreSQL / pgvector
→ 后台采集
→ 公司扩容
→ 容器部署
→ v0.2 发布
```

不要先扩公司数量。先确保真实模型、真实检索和真实证据链都能被评测。
