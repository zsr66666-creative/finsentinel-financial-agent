# Task 9：真实报告索引和可选择的检索范围

## 行为

`GET /api/v1/evidence/scopes` 从实际的固定 BGE 模型向量生成公司/期间目录，包括每份 PDF 的哈希、物理页码、片段数和覆盖类型。未建索引的报告不出现在目录中。查询的公司、期间和问题作为一次请求绑定，切换范围或修改问题使旧响应失效。目录失败提供重试，不填充演示选项。

`POST /api/v1/evidence/search/text` 保留既有请求契约，响应 `answer_status=candidates_only` 和 `data_mode=real_pdf_candidates`；不把新入库候选原文称为已复核金额证据。原有金额比较仍只覆盖已审核的 2026H1 问题范围。

本批次报告是已在 ECS 采集的立讯精密 2024 年年度报告：

- artifact ID：`05e081ae37a01bc1df83183f2b93c64590d2c2aac6dd4d0c9864743de1b105c4`
- 官方 URL：`https://static.cninfo.com.cn/finalpage/2025-04-26/1223326862.PDF`
- PDF SHA-256：`e436b5ab1775cfa05aacb4a16dd8e5c6b89e926ed18a7a55a86728bab6fcb1da`
- 本地同哈希文件为 276 页；现有解析器提取物理页 1、2、3、8、9、39、50、118、119、122、147，共 11 页，生成 328 个片段。ECS 必须重新验证实际产物，不能把本地数量当作云端实测。
- 当前选页覆盖不是全文覆盖。未来新增企业及报告仍需独立采集、来源核对和索引验收。

## 索引流程

`scripts.task9_index` 只作为管理员命令运行，不开放新的管理 API 或端口。它读取 `ingestion_artifacts`，检查文件路径位于采集根目录、身份元信息及 PDF 哈希，并重新从原始 PDF 核对每个选页的解析文本。严格保留物理页码、块偏移、原文和哈希；每个原文块按最多 320 个字符拆分，不跨页合并。超过实际 512-token 预算的片段报错，禁止静默截断。

文档向量使用既有固定版本 `BAAI/bge-small-zh-v1.5@7999e1d3359715c523056ef9478215996d62a620`、512 维、CLS、L2。文档没有查询前缀；在线问题仍使用既定检索指令。编码在独立 CPU 子进程执行，无 torch，单线程，600 秒超时，进程峰值验收上限 384 MiB。

全部验证和编码成功后才在一次数据库事务中发布片段，覆盖元信息随片段同事务发布。PostgreSQL 使用文档级事务锁处理并发重试。相同身份重跑校验原文、模型、provenance 和向量后不新增；冲突或部分旧发布状态直接失败。不新增数据库表、不修改旧 2026H1 向量。

## 验证边界

本地已用相同哈希 PDF 验证 328 个原文片段，首次新增 328、重跑新增 0。单独 ONNX 文档编码进程本机峰值约 221 MiB。营业收入、应收账款、经营现金流的开发冒烟查询在 Top-5 中找到对应原文。此项使用 SQLite 存储、NumPy 精确余弦和实际混合检索代码，不等同于 PostgreSQL、云端并发或独立评测。

`scripts.task9_acceptance` 在 ECS 对全部索引片段与原始 PDF 产物核对，再验证目录、2024FY 已知来源查询、2026H1 回归、跨范围隔离、已审核比较及待复核拒答。它是开发冒烟验收，不能用于调整冻结的独立测试集，也不宣称缺证据准确率或全文覆盖率。

## 阿里云部署

`scripts/package_task9.py --output <archive>` 只打包已提交源码，逐文件校验，检查实际归档 Shell 为 LF。包不含模型、向量、凭据或用户数据库。通过阿里云控制台上传后，校验外层归档哈希、解压并运行 `deploy/ecs/install-task9-offline.sh`。

部署脚本在旧服务继续运行时构建前端，复用 Task 8 的 ONNX 文件及 encoder venv，先创建完整 PostgreSQL 自定义格式备份。只有文档编码期间短暂停止在线 encoder，避免两份模型同时占用内存；本时间窗口文字检索可能返回可恢复的 503，首页与已审核比较仍可用。失败路径恢复 encoder。

索引重复执行验证完成后发布新的后端 drop-in 和前端构建，独立备份旧配置及 `.next`，保留旧静态资源，并通过本地和 Nginx 验证接口、五个页面及 CSS/JS。失败自动恢复后端配置及前端构建；**已成功提交的新增索引保留**，不自动破坏性恢复整个生产数据库。备份供后续受控恢复使用。

脚本不修改 Nginx、不开放 8000/8081、不修改常驻采集 worker。保留的 Task 8 release 仍提供模型和运行时，不可清理。生产构建、PostgreSQL 事务和浏览器交互在 ECS 验证前保持 pending。

## 浏览器验收

1. 登录后进入 `/compare`，公司目录显示立讯精密，报告期同时有 2024FY 与 2026H1。
2. 选择 2024FY，显示已索引页码与片段数；查询“应收账款”，原文来源为 2024FY，点击来源详情可核对哈希与物理页码。
3. 切回 2026H1，旧结果清空；新查询不混入 2024 年报。
4. 请求途中切换报告期或修改问题，旧响应不重新填入结果。
5. 明暗主题、键盘 Tab 焦点、手机宽度和高级查询包入口可用；静态资源无 404。
